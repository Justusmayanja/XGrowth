## 1. Hard boundaries

- Never log or return the API key, request bodies, scene text, voice ids tied to a user, or audio bytes. Exception messages must not include them.
- The API key comes only from `.env` through config. Never hardcode it, never put it in a URL.

- No new dependencies (use Laravel's `Http` client). No new tables. No new platform settings. No migrations.

- The sync switch must be impossible to enable in production (Part B).

## 2. Part A: ElevenLabs provider

### A1. Config
`config/services.php` gets an `elevenlabs` block, all from env:

| Env | Purpose | Default |
|---|---|---|
| `ELEVENLABS_API_KEY` | key | empty |
| `ELEVENLABS_BASE_URL` | API base | `https://api.elevenlabs.io` |
| `ELEVENLABS_MODEL` | model id | `eleven_multilingual_v2` (verify) |
| `ELEVENLABS_VOICE_FEMALE` | voice id | empty |
| `ELEVENLABS_VOICE_MALE` | voice id | empty |
| `ELEVENLABS_OUTPUT_FORMAT` | MP3 format string | verified default, for example `mp3_44100_128` |
| `ELEVENLABS_TIMEOUT` | seconds | 60 |

Add them to `.env.example` with comments. A `TikTokVideoCatalog` (or equivalent existing constants class) holds the per-model price table in **mills per character** (1 mill = $0.001), derived from the verified per-1,000-character prices, for example $0.08 per 1,000 characters is 0.08 mills per character... compute carefully and unit-test the conversion so it cannot be off by a factor of 10 or 1,000. Unknown model ids use the highest known rate (fail safe, never underestimate).

### A2. `ElevenLabsSpeechProvider implements SpeechProvider`
- `isConfigured()`: key non-empty and the voice id for the requested style non-empty. Not configured means the render fails with the standard voice-unavailable message, no HTTP call made.
- `speak()` flow, in this order: check `AiUsageService` and the spend cap the way `OpenAiSpeechProvider` does → reserve spend using the **model's real rate** (A3) → send `POST {base}/v1/text-to-speech/{voice_id}?output_format=...` with headers `xi-api-key` and `Accept: audio/mpeg`, JSON body `{ text, model_id }` (add `voice_settings` only if verified and useful, as constants) → on 200 with a non-empty audio body, write bytes to the path the caller gives (same extension and path contract as the OpenAI provider) → record usage under feature `tiktok_tts` with provider `elevenlabs` and the character count → return.
- Failure handling: timeouts set from config. Retry **only** on connection errors and 5xx, at most 2 retries with short backoff. No retry on 4xx. A 429 is a failure (release spend, standard message), logged without text. 401/403 also logs a clear operator warning ("ElevenLabs key rejected") with no secrets, and still shows the user the standard message. An empty or non-audio body counts as failure.
- Always release the reservation on any failure path, including exceptions thrown after reserve. No double release on success.
- Validate the response before writing: non-empty, and content-type `audio/*` when the header is present. The existing code measures duration with ffprobe afterwards. If ffprobe cannot read the bytes, fail the render the same way.
- Text input: scene text is already sanitised and capped at 500 characters. Do not send anything else. Language stays English only.
- The audio cache key includes provider, model, voice id, output format, and text hash.

### A3. Spend estimate fix
The shared estimate (0.015 mills per character, minimum 10) is too low for ElevenLabs. Change the reserve so each speech provider supplies its own per-character rate, with the minimum kept. OpenAI's behaviour and numbers stay exactly as they are today (tests prove it). ElevenLabs uses the rate from A1. Document in a docblock that the in-app cap is an estimate and the ElevenLabs invoice is the source of truth. The reservation is released and replaced by the recorded amount on success, as today.

### A4. Driver selection
`TikTokRenderService::speech()` supports `TIKTOK_TTS_DRIVER` values `fake`, `openai`, `elevenlabs`. Unknown values fail loudly in config validation or at first use with a clear operator log, and the render fails with the standard message (no fallback). Default stays whatever it is today so nothing changes unless the env is set. Add a small catalog of valid driver names so the string appears once.

### A5. YouTube (opt-in, separate flag)
`YouTubeFfmpegRenderer` currently uses OpenAI only when `YOUTUBE_TTS_DRIVER=openai` and a tone otherwise. Add `elevenlabs` as a third value that uses the same `ElevenLabsSpeechProvider`. Default behaviour is unchanged. Keep the change to a few lines plus a test. Do not alter YouTube's failure semantics beyond what already exists for the OpenAI branch (read them first and mirror them, and tell me what they are).

## 3. Part B: local sync rendering

- In `AppServiceProvider`, next to the existing test-time override, force the `renders` connection to `sync` when `config('tiktok.render_sync')` (from `TIKTOK_RENDER_SYNC`, default false) is true **and** the environment is not production. Use `app()->environment('production')`. If the flag is true in production, **do not apply it**, and log one operator warning at boot ("TIKTOK_RENDER_SYNC ignored in production"). Never throw at boot.
- Dev behaviour with the flag on: `tiktok:run`, `POST /api/tiktok/run`, and setup completion render the MP4 before the request returns. Opening the dashboard still starts nothing. Confirm remains a separate step.
- With sync on, a render exception must still never make `run()` or `confirm()` fail (the existing catch-and-log stays). The render state ends `failed` with the plain note.
- Document in `docs/VIDEO_RENDERING.md` and `docs/QUEUE_WORKER.md`: the flag, that a request holds for the whole encode (often a couple of minutes), that `/dev/tiktok-states` shows layout only and will not play a generated file, how to set `TIKTOK_FFMPEG` / `TIKTOK_FFPROBE` when the binaries are not on PATH, and that production uses the Redis worker.
- Add `TIKTOK_RENDER_SYNC=false` to `.env.example` with a "local development only" comment.

## 4. Tests

Use the repo's runner, the isolated DB, `Http::fake()` and `Http::preventStrayRequests()`.

**ElevenLabs provider**
- Success: correct URL (voice id in path, `output_format` query), `xi-api-key` header present, body has `text` and `model_id`, audio bytes written, usage recorded under `tiktok_tts` with the right character count, reservation released/replaced, no leftover reserve.
- Female and male styles pick the right voice id. Missing key or missing voice id: no HTTP call, standard failure message.
- 4xx (400, 401, 403, 422): no retry, reservation released, render fails with the standard message, no usage row. 429: same. 5xx: retried then fails, reservation released once. Connection error: retried then fails.
- Empty body or non-audio content-type: failure, nothing written, reservation released.
- Daily cap full and monthly cap full: refuses before any request, no reservation, no usage row.
- Estimate: ElevenLabs reserves the model rate (assert numbers for both known models and an unknown model falling to the highest), and the OpenAI reserve is byte-for-byte unchanged. Conversion unit tests prove the mills-per-character math.
- Audio cache: a retry in the same job does not call the API twice. A different provider or voice does not reuse the cache.
- Privacy: captured logs and thrown exception messages contain no API key, no scene text, and no response body.
- No silent fallback: with the driver set to `elevenlabs` and the API failing, the provider never delegates to the fake or OpenAI provider.

**Driver selection**
- `fake`, `openai`, `elevenlabs` resolve to the right class. Unknown value fails with the standard message and an operator log. Default unchanged.

**YouTube**
- `YOUTUBE_TTS_DRIVER=elevenlabs` uses the provider. Unset and `openai` behave as before (existing tests stay green).

**Sync flag**
- `TIKTOK_RENDER_SYNC=true` in local/testing: the `renders` connection resolves to `sync`.
- `TIKTOK_RENDER_SYNC=true` in production: connection unchanged, warning logged, no exception.
- Flag false: unchanged.
- With sync on, `run()` returns a clip whose render is already `ready` (use the fake speech driver and the existing `ffmpeg` test group, skipping if ffmpeg is missing).
- With sync on and a failing provider, `run()` still returns the created clip and the render state is `failed`.
- A GET of the dashboard still dispatches nothing.
